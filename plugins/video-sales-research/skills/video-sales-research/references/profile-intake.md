## Processing rules

- Keep all submitted facts scoped to the current chat and current user.
- Classify each submitted URL as a company site, portfolio, video channel, social profile, or other reference.
- Do not make the user retype work already supported by portfolio pages.
- Do not infer unlisted responsible stages, software, equipment, permissions, or client relationships.
- Ask follow-up questions only when a missing stable fact prevents safe research. Ask all essential questions together.
- Do not treat compensation, travel expense, lodging, paid trial, dates, delivery schedule, volume, nights, weekends, onsite work, remote work, revision counts, payment terms, rights, source-file delivery, NDA, rentals, or industry-specific safety requirements as onboarding gaps.
- Keep URL sharing permission separate from the fact that a URL is public.
- On confirmation, summarize stable facts, fixed exclusions, extracted work evidence, unresolved essentials, and the current user's settings.
- Do not create a profile for one user from another user's prior conversation or files.
- Reject or redact submitted passwords, authentication codes, API keys, access tokens, private keys, identity-document numbers or images, payment-card data, bank login details, and recovery phrases. Explain that these are unnecessary for profile registration.
- Do not copy profile content into a plugin source folder, Git repository, public issue, public link, or diagnostic log.
